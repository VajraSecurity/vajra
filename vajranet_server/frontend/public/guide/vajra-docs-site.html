System requirements

What you need on the server side to run Vajra, and what an endpoint needs to run the agent.

Day-to-day user? Skip to Endpoint (agent) requirements — the server side is your administrator's concern.

Server (platform) requirements

Requirement Why it's needed
Linux server Installs as native services — no containers
Node.js v20.19+ with npm 10+
PostgreSQL Two databases: accounts/sessions/audit, and fleet/device data
Redis Recommended for production — sessions, rate-limiting, multi-instance scaling
A domain name + TLS certificate Protects credentials and session cookies in transit

Browser requirements

A current version of Chrome, Edge, Firefox, or Safari.

  • JavaScript and cookies enabled — Vajra is a single-page app and uses a session cookie to keep you signed in
  • Blocked cookies mean you can't stay logged in, even after a correct password

Endpoint (agent) requirements

An "endpoint" is any laptop, server, or workstation you want Vajra to monitor. Each one runs a small background program called the agent — see Components and Installation.

Platform Notes
Windows Supported, with an installer package provided by your Vajra administrator
Linux Supported, with an installer package provided by your Vajra administrator
macOS Not yet supported — on the roadmap
  • Outbound access to your Vajra server over HTTPS (periodic data) and WebSocket (real-time status and commands)
  • Firewalls/proxies must allow that traffic — a blocked device just never shows up in My Devices (see FAQ)

On-premises vs. cloud

  • On-premises — your own server, direct access to your local network. Unlocks network discovery and vulnerability scanning.
  • Cloud — hosted by your provider. Identical experience, except those two network-scanning features don't apply.

Agents connect to your server the same way either way. See Set up on-premises and Set up in the cloud.

Components

A tour of every item in the Vajra sidebar — what each one is for, at a glance.

Sidebar goes broad to narrow: Dashboard first, then a device or alert, then specialized tools only when needed. Items marked Super Admin are hidden entirely from Group Admins and Viewers, not just disabled. Items also marked Group Admin are visible to Group Admins too, but scoped to their own assigned group's devices — never the whole fleet.

2.1Dashboard

Fleet health at a glance, shown right after sign-in. No actions here — just the big picture.

  • Stat cards — total devices, protection coverage, active alerts, alerts this week
  • Weekly alert trend chart — spot a spike by severity and type
  • OS / protection breakdowns — donut charts for patch planning
  • Top alerting / top USB activity — ranked tables, no filter needed

Example: alert chart spikes Tuesday → check Alerts for what happened.

2.2My Devices

Your full device inventory — where most investigations start.

  • Status per device: Online, Offline, or manually flagged Critical
  • Search by name, filter by group
  • Rename, flag critical, or bulk-select devices
  • Click in for compliance status, patch history, firewall, Secure Boot/TPM, resource graphs

Example: lost laptop → find it here, mark Critical, then isolate it via Policy Management (Super Administrator, or a Group Admin for their own group's devices).

2.3Alerts

Every detection Vajra has raised — triage it, assign it, or report it.

  • Filter by severity, device, status, date range
  • Assign to yourself or a teammate — "My Alerts" shows your queue
  • Track status: in progress → resolved → closed
  • Generate a CERT-In incident report from selected alerts — pre-filled, saved as draft, exported as PDF
  • ClamAV antivirus scan-status summary

Example: three devices flag the same process → select all three, file one CERT-In report instead of three.

2.4Compliance

CERT-In / SEBI / IRDAI status, plus Vajra's own baseline. See Compliance for what each framework covers.

  • Score per framework, plus a baseline checklist
  • Historical trend — improving, flat, or slipping
  • Per-device pass/fail detail as a task list
  • One-click PDF export, org-wide or per framework

Example: audit next week → export last quarter's CERT-In trend as a PDF in under a minute.

Find what's not in your inventory, and check known systems for known vulnerabilities. See Network Security for a full walkthrough.

  • Vulnerability Scanner — drive Nessus / OpenVAS / Burp Suite, review ranked findings
  • Scan Scheduler — watch a subnet on a recurring schedule and auto-fingerprint any new unmanaged host

Search your fleet directly — for when there's no alert yet for what you're after.

Why Vajra

Endpoints are where most breaches actually start, and where most compliance audits actually fail. Vajra gives you one console to see every device, prove its posture, and act on it — without slowing your team down.

Security: see it, then stop it

An unmanaged laptop or a device with USB storage silently re-enabled is a blind spot an attacker only needs to find once. Vajra keeps every enrolled device in view — online status, risk signals, and suspicious activity — and gives you the response actions to act immediately: isolate a device from the network, block a port or IP, disable USB or Bluetooth, or drop into a remote shell, all from the same console you use to monitor the fleet. No separate tool, no waiting on a site visit.

Compliance: evidence, not guesswork

Regulated teams don't just need to be compliant, they need to prove it, on demand, against a named baseline. Vajra runs an 18-point compliance check against SEBI, IRDAI, and CERT-In requirements on every device and keeps the results as a running record — so an audit becomes a report you already have, not a scramble to reconstruct one. Every sensitive action is written to an audit trail: who did what, to which device, and when.

Access control that matches how your team is actually organized

Security tooling is itself a risk if everyone who can see a device can also isolate it or run a shell on it. Vajra's role-based access lets you scope administration to a group and its devices: a Group Admin can act on their own team's fleet — manage policies, run remote shell, isolate a device — while a Group Viewer can see the same fleet without being able to change anything. A Super Administrator retains full, unrestricted control across every group. Access follows your org chart, not a single shared admin login.

An AI Assistant that asks before it acts

Instead of writing queries or digging through screens, ask Vajra's AI Assistant plain-language questions about your fleet — which devices are non-compliant, what changed overnight, which group a device belongs to. When a question calls for a real action, like isolating a device, the assistant proposes it and waits for you to confirm before anything is dispatched to the agent. You stay in control of every action taken on your infrastructure.

Built to be usable, not just powerful

A console nobody can operate under pressure doesn't help during an incident. Vajra's interface keeps the information you need most — device status, alerts, compliance state — visible without digging, works the same way whether you're hosting it yourself or running it in the cloud, and scales from a handful of devices to a full fleet without changing how you work.

Getting started: set up on-premises

Stand up Vajra on your own server. For the person deploying the platform for their organization.

Topology

Installs directly onto a Linux host — no containers. Web console, API service, and both databases run as native services. See System Requirements for what the server needs.

Setup steps

  1. Install the platform

    Install the console and API service using your vendor-provided install package, then point both at PostgreSQL and Redis.

  2. Put it behind HTTPS

    Always https://, with a valid certificate. A reverse proxy (e.g. nginx) is the usual way to terminate TLS.

  3. Create the first account

    Register in your browser. The first account created automatically becomes the Super Administrator — keep its password and MFA recovery codes safe.

  4. Turn on analytics (optional)

    Fleet-wide CVE/compliance dashboards — see Components → Analytics. Can be added later.

  5. Roll out agents

    Install the agent on each device — see Installation. Appears in My Devices within a minute or two. Not showing up? Check outbound network access — see System Requirements → Endpoint requirements.

⚠️
There's no public sign-up

No public "create an account" page, deliberately. Every teammate must be invited by the Super Administrator — see Team Management.

What to expect afterward

  • Invite your security team (Team Management)
  • Roll out agents to your highest-priority devices first
  • Set up device groups so Group Admins and Viewers only see what's relevant

No need to enroll every device up front — add them incrementally at any time.

Installing the agent on Windows

Two walkthroughs, depending on whether you have local Administrator rights on this device.

Navigating this tab

Across the top of the page sits a row of horizontal tabs: With Admin Rights and Without Admin Rights. Clicking a tab swaps the entire panel below it — before-you-start notes, the install walkthrough, and troubleshooting — for that path, without leaving the page.

With admin rights

The standard path: installing as (or with help from) a local administrator, so the agent runs as a proper Windows service.

Before you start

You need: the download link from your administrator, and local Administrator rights on this device (not domain admin).

Installing

  1. Run the installer as an administrator

    Right-click the .exe from your administrator's link → "Run as administrator." Don't just double-click it. Click Next on the welcome screen.

  2. Accept the license agreement

    Check "I accept the terms in the License Agreement," then Next.

  3. Leave admin privileges enabled

    Keep Allow Admin Privileges (full service) checked — this is what makes it a proper Windows service instead of a reduced, per-user install. Enable Allow Remote Shell Access too, if your Vajra administrator wants remote command access to this endpoint.

  4. Start the install

    Click Install on the summary screen.

  5. Let it finish

    Registers and starts as a Windows service. No restart needed.

  6. Click Finish

    Closes the Setup Wizard.

Confirming it worked

Connects automatically — no manual "enroll" step. A "Connected" flyout confirms it from the system tray, and it appears in My Devices as Online within a minute or two. Or check Windows Services (services.msc) for "Running."

✅
Why admin rights matter here

Elevated rights let the agent run as a background service — protecting the whole machine, not just your session — and apply system-wide settings like firewall/USB control.

If it doesn't show up

  • Double-check the UAC prompt was actually approved
  • Confirm outbound network access — see System Requirements
  • Check the service status in Windows Services — "Stopped" means a config issue
  • Check antivirus/endpoint-security quarantine or logs — it may have blocked the installer

Without admin rights

If you're not a local administrator on your machine — common on company-managed laptops where IT retains control — you have two realistic options.

Option 1: ask IT to deploy it for you (recommended)

Most locked-down organizations already push software via a device-management tool (Intune, SCCM, etc.) — no elevated rights needed on your end. Just confirm you're in scope for the rollout.

Option 2: a per-user install, if supported

The same Setup Wizard your administrator hands out for the admin-rights install — run it, but leave Allow Admin Privileges unchecked on the access screen for a reduced, per-user install instead. Ask your administrator if this "Reduced mode" is enabled for your organization.

  • Runs under your own session, not as a system-wide service
  • Only active while you're logged in
  • Narrower coverage than an admin-rights install — no remote shell
  1. Run the installer

    Click Next on the welcome screen.

  2. Accept the license agreement

    Check "I accept the terms in the License Agreement," then Next.

  3. Leave admin privileges unchecked

    Untick Allow Admin Privileges (full service) — this greys out Remote Shell Access and switches the install to Reduced mode.

  4. Start the install

Installing the agent on Linux — graphical installer

The recommended path on a Linux desktop: a point-and-click installer that asks you directly whether to install in Full or Reduced mode — no need to know your sudo status up front.

Before you start

You need: the graphical installer from your administrator. Run it with sudo (or as root) for Full mode, or as your own user for Reduced mode — the installer itself will offer whichever modes are actually available.

Installing

  1. Accept the license agreement

    Read the terms, then Next.

  2. Choose Full or Reduced mode

    Full mode runs the Vajra and remote-shell extensions as a root systemd service. Reduced mode installs baseline telemetry only, as a limited per-user service — pick this if you don't have admin access.

  3. Allow remote shell access (Full mode only)

    Only shown if you chose Full mode in the previous step. Enable it if your Vajra administrator needs remote command access to this endpoint.

  4. Confirm and install

    Review the summary, then click Install.

  5. Done

    Confirms which mode was installed. Click OK to close.

Confirming it worked

Appears in My Devices as Online within a minute or two. Full mode: systemctl status vajra should show "active (running)." Reduced mode: systemctl --user status vajra.

If it doesn't show up

  • Check the install log — vajra_install_log.txt, written next to the installer
  • Confirm outbound network access — see System Requirements
  • Reduced mode installed under the wrong account? Make sure you ran the installer as the user you intend to monitor

Uninstalling the agent on Windows

Run vajra_uninstall.bat as an administrator. No token or password is needed.

Uninstalling

  1. Open the windows_agent folder

    Use the folder from the package you installed with, or download the package again.

  2. Run the uninstaller as administrator

    Right-click vajra_uninstall.bat and choose Run as administrator.

  3. Let it finish

    It stops the vajra service and removes the files in C:\Program Files\osquery. If osquery was already on the machine before Vajra, only Vajra's files are removed and the original is restored. No restart is needed. The device stops reporting to Vajra immediately.

Confirming it worked

Windows Services (services.msc) no longer lists a vajra service. The device eventually shows Offline in My Devices and stops updating.

If it won't uninstall

  • Not running as administrator — right-click → "Run as administrator" and try again
  • "The Vajra EDR service does not exist" — the agent may already be removed
  • Details are written to vajra_uninstall_log.txt next to the script

Login and MFA

How to sign in, secure your account with multi-factor authentication, and what to do if you get locked out.

Signing in

  1. Go to your organization's Vajra address

    Same address for everyone — no separate URL per person. Enter your email and password on the sign-in screen.

  2. Solve a CAPTCHA, if asked

    Shows up after several failed attempts. Normal, not a sign of a problem — just prove you're human and try your password again.

  3. Enter your MFA code, if enabled

    The 6-digit code from your authenticator app. Lost your device? Use a recovery code instead.

On success, you land on My Devices. Your session stays signed in until it expires or you sign out.

Setting up multi-factor authentication

Password plus a rotating phone code — strongly recommended for every account, especially Super Administrator and Group Admin. From Settings:

  1. Open Settings → Security

    Choose "Set up multi-factor authentication."

  2. Scan the QR code

    With any authenticator app (Google Authenticator, Authy, 1Password, etc.).

  3. Confirm with a code

    Enter the current 6-digit code from your authenticator app to confirm the pairing.

  4. Answer two security questions

    Backs up recovery if you lose your authenticator app.

  5. Save your recovery codes

    Store them in a password manager. Each works once.

🔑
Locked out?

Use a recovery code at login. Both gone? Ask your Super Administrator to reset via Team Management — there's no other way back in, by design.

Changing your password

Settings → Security → Change password. Confirm your current password first. A forced reset (from an admin) blocks the rest of Vajra until you set a new one.

🛡️
A note on brute-force protection

Sure your password is right? Check caps lock or a stale saved password first. Repeated failures trigger the CAPTCHA shown above.

Roles

Three roles, each a strict subset of the one above it.

Creating a group

Network scanning

Find devices on your network that Vajra doesn't manage yet, then dig into any of them.

Network Security — tab 1 of 3

Want this to happen automatically instead of by hand? See Scan Scheduler.

Running a discovery scan

Enter a target IP or comma-separated list (private ranges only — 10.x, 172.16–31.x, 192.168.x), optionally narrow it with a CIDR range, and give a reason for the scan (kept for audit purposes). Start the scan, or cancel it mid-run if needed.

Reading the results

Discovered addresses are grouped by subnet, and each one is tagged:

  • Managed by Vajra — already enrolled; matches a known device
  • Unmanaged — responded to the scan but isn't enrolled — worth investigating
  • New — wasn't present in the previous scan of this range
  • Disappeared — was present before but didn't respond this time

A summary chart and a latest-scan overview sit alongside the results for a fleet-wide view before you drill into individual addresses.

Per-device actions

Select one or more addresses (up to 50 at a time) within a subnet and run:

  • Advanced Scan — an Nmap-style fingerprint: OS guess, device type, running services, MAC address, uptime, and TCP/IP sequence details
  • Vuln Scan — a quick, template-driven check with a choice of profile: Security Posture Assessment (CVEs, misconfigurations, default credentials, and exposures — recommended first), CVE Scan (critical/high/medium CVEs only), Misconfiguration Scan (default creds, exposed admin panels, open databases), or Full Scan (every template, including info-level findings)
💡
Not the same as the Vulnerability Scanner tab

This is a fast, built-in check for triaging what a discovery scan turns up. For a full Nessus / OpenVAS / Burp Suite assessment, use Vulnerability Scanner.

Scan history

Choose History to review past scan sessions for this fleet, without re-running them.

Step-by-step process

  1. Step 1: Enter the scan details

    In the Target IP field, enter one address or a comma-separated list (private ranges only — 10.x, 172.16–31.x, 192.168.x). Optionally narrow the sweep with a CIDR range, then fill in a short Reason for Scan — it's kept for audit purposes.

    After this: the Run Scan button becomes active once both the target and reason are filled in.

  2. Step 2: Start the scan

    Select Run Scan.

    After this: a progress indicator appears. You can select Cancel at any point to stop the scan early — results gathered so far are kept.

  3. Step 3: Review the discovered addresses

    Once the scan finishes, results appear grouped by subnet.

    After this: each address is tagged Managed by Vajra, Unmanaged, New, or Disappeared (see above for what each means). Unmanaged and New addresses are usually the ones worth a closer look.

  4. Step 4: Select the address(es) to investigate

    Tick the checkbox next to one or more addresses within a subnet (up to 50 at a time), or use "select all" for that subnet.

    After this: the Batch Advanced Scan and Batch Vuln Scan actions become available for the selected addresses.

  5. Step 5: Run a per-device scan

    Choose Advanced Scan for an Nmap-style fingerprint, or Vuln Scan and pick a profile — Security Posture Assessment, CVE Scan, Misconfiguration Scan, or Full Scan.

    After this: the scan runs in the background; once it completes, the same button changes to View Result so you can open the findings.

    Note: this is a fast, built-in check — for a full Nessus / OpenVAS / Burp Suite assessment, use Vulnerability Scanner instead.

Scan scheduler

Set it once, and Vajra keeps watching the subnet for you — flagging and fingerprinting new unmanaged hosts automatically.

Network Security — tab 3 of 3

How it works

A schedule re-runs a discovery scan against its target range on whatever cadence you set. Any address that responds and isn't already Managed by Vajra — and isn't on the schedule's own Known IPs exclude list — is treated as a new unmanaged host, and the schedule automatically fires an Advanced Scan (the same Nmap-style fingerprint available from Network Scanning) against it. Nothing needs to be triggered by hand once the schedule is saved and enabled.

Creating a schedule

Select New Schedule and fill in:

  • Name — something recognizable, e.g. "Office subnet watch"
  • Target IP / CIDR — the range to keep watching
  • Frequency — Every 5 minutes, Every hour, Every day, or a Custom interval (a number plus minutes/hours/days)
  • Reason — kept for audit purposes, same as a one-off scan
  • Known IPs (optional) — devices that will never run the Vajra agent, like routers or printers; add each one and press Enter or Add IP
💡
Why exclude known devices

An address on the Known IPs list is never flagged as a new unmanaged host and never auto advanced-scanned by that schedule — useful for hardware that will never carry a Vajra agent, so it doesn't clutter every run's results.

Managing schedules

Each saved schedule appears as a row in the Schedules list, showing:

  • An enable/disable toggle — a disabled schedule stays saved but stops running
  • A status badge — Never run, Running, Success, or Failed
  • Last run, as a relative time (e.g. "12m ago")
  • New hosts found on the last run, with a "pending" count if more unmanaged hosts were queued than that run's per-tick cap could process — they're picked up on a future run

From the same row: Run Now triggers an immediate run without waiting for the next scheduled tick; Edit reopens the form with its current values; Delete removes it after a confirmation prompt.

Run history

Select View Runs on a schedule to expand its run history — each entry shows the target, timestamp, how many hosts were discovered, and the fingerprint results for any hosts that were auto advanced-scanned that run.

Frequently asked questions

Quick answers to the questions we hear most often.

Can I create my own account?

No — only a Super Administrator can add new teammates, from Management → Team. This keeps access to your fleet tightly controlled.

What's the difference between a Group Admin and a Viewer?

Both only see the device groups they've been assigned to. A Group Admin can triage alerts, review compliance, and manage devices in those groups; a Viewer can only look. Isolating a device, blocking traffic, or running a scan still requires a Super Administrator — see Team Management for the full capability breakdown.

Can the AI assistant do something harmful by mistake?

No — it can look up information freely, but any action that affects a device (isolating it, blocking traffic, changing a setting) always requires a Super Administrator's explicit confirmation first.

Why can't I see the Network Security page?

Network scanning needs direct access to your local network, so it's only available for on-premises deployments, and only to Super Administrators. See Network Security and System Requirements.

Where do vulnerability scan results get stored?

For Nessus and OpenVAS, Vajra shows you results live from the scanner itself rather than storing a separate copy. Burp Suite results are kept in Vajra a bit longer so they remain viewable after they'd otherwise age out.

How do I remove Vajra from a device?

Run the uninstaller on that device — no token is needed. See Uninstalling — Windows or Uninstalling — Linux.

I can't log in — what should I check?

Double-check your email and password, and wait a moment before retrying if you're asked to solve a CAPTCHA. If you've lost access to your authenticator app, use a saved recovery code, or ask your Super Administrator to reset your password and MFA.

A device shows "Offline" but I know it's powered on — why?

Check the device's network connection first — it can take a minute or two after reconnecting for status to update. If it stays offline longer, ask your administrator to check whether the agent service is still running.

A vulnerability scan won't start — what should I check?

Confirm the scanner (Nessus/OpenVAS/Burp Suite) is connected under its Settings tab in Network Security → Vulnerability Scanner — ask your administrator to verify the connection details if it still won't launch.

I don't have admin/sudo rights on my machine — can I still get the agent installed?

Yes, usually. See Windows — without admin rights or Linux — without sudo. Most IT teams deploy it centrally either way.

Do I need to pick between CERT-In, SEBI, and IRDAI compliance?

No — Vajra tracks all four frameworks independently for every device. View and export whichever are relevant. See Compliance.

Can a Group Admin promote themselves to Super Administrator?

No. Roles can only be changed by an existing Super Administrator, from Management → Team. There is no self-service way to change your own role, by design.

What happens to a device's data if I remove it from a group?

Nothing is deleted — the device stays fully enrolled and monitored. Removing it from a group only changes who can see it; a Group Admin or Viewer who was scoped to that group simply loses visibility into that specific device going forward.

The Vajra baseline

Vajra's own built-in security-hygiene checklist, shown as the "Control pass-rate for Vajra Compliance" table above. Applies to every device, regardless of which regulations apply to your organization.

  • Patch and update status — is the OS and key software up to date?
  • Endpoint protection — is antivirus/Defender installed, enabled, and current?
  • Firewall configuration — is the local firewall active with sane rules?
  • Removable media control — is USB storage appropriately restricted?
  • Authentication hygiene — MFA enabled, password policy met

Doesn't depend on external regulation — the fastest "are we in reasonable shape" answer for a device or your whole fleet.

SEBI

Cyber Security and Cyber Resilience Framework for regulated market entities — brokers, depositories, mutual funds. Covers governance, access control, network security, data protection, incident response, periodic VAPT audits.

  • Device checks mapped to SEBI's technical control areas
  • Organization-wide scoring for periodic submissions
  • Trend view demonstrating sustained control over time

Cybersecurity guidelines for insurers — similar ground to SEBI, tailored to policyholder data sensitivity.

  • Device checks mirroring the SEBI mapping, adjusted for insurers
  • Organization-wide scoring for IRDAI reporting
  • Same trend and per-device drill-down as the other frameworks

CERT-In

India's national cybersecurity incident response agency. Its 2022 directions require reporting qualifying incidents within 6 hours of detection, log retention, and baseline security hygiene.

  • Per-device CERT-In checklist — patch status, logging, endpoint protection
  • 6-hour incident reporting — build a report directly from selected alerts (see Components → Alerts)
  • Historical compliance trend as evidence of ongoing adherence
